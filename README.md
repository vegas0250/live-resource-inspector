# Live Resource Inspector

Расширение Chrome (Manifest V3) для пассивного разбора текущей вкладки: сетевые запросы, ссылки и ресурсы из DOM, записи Performance Resource Timing. Свой сервер не используется, собранные URL остаются на устройстве.

## Требования

- Node.js 20 или новее
- Актуальный стабильный Chrome 120+

## Команды

```bash
npm install
npm test
npm run typecheck
npm run lint
npm run build
npm run fixtures
```

`npm run dev` собирает расширение и оставляет Vite в режиме наблюдения. После изменения кода на странице `chrome://extensions` нужно нажать «Обновить».

`npm run fixtures` поднимает страницы сценариев на `http://127.0.0.1:4173`.

## Установка

1. Выполнить `npm run build`.
2. Открыть `chrome://extensions`.
3. Включить режим разработчика.
4. «Загрузить распакованное расширение» и выбрать папку `dist`.

Публикация в Chrome Web Store не настроена.

## Использование

1. Открыть обычный сайт (`http` или `https`).
2. Нажать иконку расширения.
3. Нажать «Начать» и разрешить доступ к сайтам. Разрешение запрашивается в момент старта, а не при установке.
4. «Открыть анализатор» показывает полную страницу: домены, ресурсы, ссылки, медиа и журнал запросов.
5. «Пауза» перестаёт принимать новые записи. «Очистить» удаляет только текущую сессию; при большом объёме спрашивает подтверждение.

Поиск идёт по всему набору сессии. Категории комбинируются с текстом. Длинные списки виртуализированы. Большой экспорт, который не помещается в буфер обмена, сохраняется файлом.

Область сбора в настройках:

- «Только текущий документ» — полная навигация или перезагрузка начинает новую сессию. Переходы SPA остаются в текущей.
- «Вся вкладка» — одна сессия живёт через загрузки и SPA.

## Ограничения

Расширение не обещает увидеть каждый сетевой обмен.

- `webRequest` не показывает кадры WebSocket и закрытие соединения, только рукопожатие.
- `blob:` записывается как локальный адрес. Это не URL сервера. Рядом может быть исходный адрес из DOM или сети.
- `data:` не сохраняется: такие URL часто содержат само содержимое.
- Недоступны `chrome://`, Chrome Web Store, страницы других расширений и часть внутренних запросов браузера.
- Запросы видны только для сайтов, на которые пользователь выдал доступ, и только если доступ есть и к инициатору, и к адресу запроса.
- Предполётные CORS-запросы не запрашиваются: для них нужен `extraHeaders`, а вместе с ним расширение начало бы видеть cookies.
- Тела запросов, cookies, пароли и заголовки авторизации не читаются и не экспортируются.
- Файл `file://` намеренно не входит в запрашиваемый доступ.
- Песочница iframe, DRM и закрытые медиаконтексты могут не отдать исходный адрес.
- Service worker может быть остановлен. Записи пишутся в IndexedDB пачками; при убийстве процесса в момент записи возможна потеря последней пачки. Открытый анализатор держит соединение и уменьшает этот промежуток.
- После полного перезапуска браузера идентификаторы вкладок меняются. Старые сессии остаются в базе как архив, но не привязываются к новым вкладкам.
