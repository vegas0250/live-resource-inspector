# Архитектура

## Поток данных

1. После установки service worker сам открывает сессию для уже открытых вкладок `http` и `https`. Новая загрузка и первое сетевое событие тоже создают сессию, если вкладка не на паузе.
2. `content.js` внедряется в кадры наблюдаемой вкладки.
3. Три источника присылают наблюдения:
   - `chrome.webRequest`: старт, редирект, завершение, ошибка. Слушатели регистрируются синхронно на верхнем уровне service worker и ничего не блокируют.
   - Content script: обход DOM, `MutationObserver` только по добавленным узлам и изменённым атрибутам, `PerformanceObserver` для `resource`.
   - Resource Timing дополняет сеть и DOM, но не заменяет их.
4. `SessionState` нормализует URL, классифицирует запись и дедуплицирует ресурсы по `sessionId + normalizedUrl`.
5. Пачка изменений пишется в IndexedDB. Анализатор читает ту же базу и получает сигнал `DIRTY` по порту.

Память service worker не является хранилищем. Метаданные активных сессий лежат в `chrome.storage.session` (если он недоступен — в `chrome.storage.local`). Сами записи — в IndexedDB. Настройки — в `chrome.storage.local`.

## Модули

| Путь | Роль |
|---|---|
| `src/background` | Service worker, сессии, приём сети и DOM |
| `src/content` | DOM, MutationObserver, Resource Timing |
| `src/collector` | Состояние сессии, дедупликация, счётчики |
| `src/classifier` | Правила категорий |
| `src/storage` | IndexedDB и настройки |
| `src/filters` | Поиск, категории, сортировка |
| `src/export` | TXT, CSV, JSON и решение «буфер или файл» |
| `src/popup` | Мини-дашборд: те же счётчики, клик открывает анализатор в выбранном разделе |
| `src/dashboard` | Полный анализатор |
| `src/shared` | Типы, URL, подписи |

## Запись ресурса и запись запроса

Один URL, запрошенный несколько раз, остаётся одним ресурсом: растут `hitCount` и `networkHits`, источники складываются. Журнал запросов хранит отдельную строку на `requestId` и обновляет её по фазам. Редиректы не создают новый `requestId`: цепочка лежит в `redirects`, конечный адрес дополнительно становится ресурсом.

Ключ сравнения снимает фрагмент `#`, приводит хост к нижнему регистру и убирает порты по умолчанию. Query-параметры остаются и в исходном URL, и в ключе. Разные query не сливаются. Совпадение домена или имени файла тоже ничего не сливает.

Инициатор сохраняется без логина, пароля, query и фрагмента, чтобы не тащить в базу токены из адреса страницы. URL самого ресурса не очищается: параметры могут быть нужны, чтобы открыть файл.

## Классификация

`classify()` собирает сильные и слабые признаки: MIME, расширение, тип `webRequest`, элемент DOM, `initiatorType` из Resource Timing. Слабый признак (например, путь `/api/` без MIME и без XHR) даёт категорию с пометкой «возможное совпадение». Если сильных признаков нет вообще, категория — «Прочее», подпись — «Неизвестный тип».

`radioCandidate` включается отдельным порогом. Обычный `.mp3` и HLS `.m3u8` радио не становятся. `gameCandidate` не ставится голому `.wasm`: нужен ещё игровой контекст — путь, имя движка или маркеры страницы (`phaser`, `unity`, `godot` и другие). Маркеры читаются из адресов скриптов, `link` и `meta generator`, без перехода в основной мир страницы и без исполнения найденного JavaScript.

Правила расширения собраны в таблицу `EXTENSION_CATEGORIES`. Новый тип добавляется туда или отдельным условием в `classify()`, без отдельного движка правил.

## Вкладки

`byTab` сопоставляет вкладку с активной сессией. Чужая вкладка в `observeNetwork` отбрасывается. В режиме документа `webNavigation.onCommitted` для главного кадра при другой URL или перезагрузке архивирует сессию и открывает новую. `onHistoryStateUpdated` только обновляет адрес страницы.

Пауза оставляет данные и перестаёт принимать наблюдения. Очистка удаляет записи сессии из IndexedDB.

После пробуждения service worker активные сессии читаются из storage и заново наполняются из IndexedDB, чтобы дедупликация продолжила те же идентификаторы. Скрипт страницы внедряется повторно.

## Производительность интерфейса

События не перерисовывают тысячу DOM-узлов. Service worker копит грязные записи и пишет их одной транзакцией. Анализатор забирает только строки с `rev` больше уже увиденного и рисует видимое окно через `@tanstack/react-virtual`. Поиск фильтрует полный массив в памяти, а не текущие DOM-строки. Повторный одинаковый запрос к модели кэшируется до следующей ревизии.

Лимиты по умолчанию: 80 000 уникальных URL и 20 000 строк журнала на сессию. На 80% появляется предупреждение. После потолка новые URL не добавляются, уже известные продолжают обновляться. Старые строки журнала вытесняются, а общий счётчик запросов не уменьшается.

## Экспорт

CSV экранирует кавычки, запятые и переводы строк и пишется частями по 1000 строк. JSON строится из явного списка полей. В нём нет cookies, `Authorization`, тел и сырых заголовков. Текст длиннее 500 000 символов не отправляется в `clipboard.writeText`, а скачивается файлом. Ошибка буфера тоже приводит к файлу.
