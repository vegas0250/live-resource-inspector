# Разрешения

Манифест использует Manifest V3. Блокирующего `webRequest`, `declarativeNetRequest`, `cookies`, `downloads` и удалённого кода нет.

## Обычные разрешения

| Разрешение | Зачем |
|---|---|
| `webRequest` | Наблюдение за стартом, редиректом, завершением и ошибкой запроса. Обработчики не возвращают `BlockingResponse` и не меняют запрос. |
| `storage` | Настройки и запасной список активных сессий. Большие записи лежат в IndexedDB, не в `chrome.storage`. |
| `tabs` | Прочитать URL и заголовок выбранной вкладки, открыть анализатор, отправить команду кадрам. |
| `activeTab` | Прочитать адрес вкладки в popup, пока service worker ещё поднимает сессию. |
| `scripting` | Внедрить `content.js` в наблюдаемую вкладку. Постоянной регистрации content script в манифесте нет: скрипт ставится при старте сессии. |
| `webNavigation` | Отличить полную навигацию от перехода SPA и заново внедрить скрипт в новый документ и iframe. |

## Доступ к сайтам

Доступ к сайтам задан в `host_permissions` и действует сразу после установки:

- `http://*/*`
- `https://*/*`
- `ws://*/*`
- `wss://*/*`

Шаблон `*://*/*` покрывает только `http` и `https`. Для рукопожатия WebSocket нужны отдельные схемы: в Chromium `ws` и `wss` входят в допустимые схемы match pattern, а звёздочка схемы их не включает.

Без этого доступа расширение не видит чужие подресурсы. С Chrome 72 событие `webRequest` приходит только если есть доступ и к URL запроса, и к его инициатору. Доступ к одному текущему origin не показывает CDN, шрифты и медиа на других доменах. `activeTab` этот доступ не заменяет: он временный и не покрывает сторонние адреса.

Сессия вкладки создаётся сама при загрузке страницы и при первом сетевом событии. «Пауза» останавливает приём, пока пользователь не нажмёт «Продолжить».

`file://` не запрашивается. Его всё равно пришлось бы отдельно включать в карточке расширения, а сценарий рассчитан на обычные сайты.

## Что сознательно не читается

- Тело запроса: в `extraInfoSpec` нет `requestBody`.
- Cookie и `Authorization`: нет `extraHeaders`. Из заголовков ответа берётся только `Content-Type`.
- Пароли и поля форм. У формы может быть прочитан только атрибут `action`, если он попадёт в общий обход URL-атрибутов; значения полей не читаются.
- Сообщения WebSocket. API отдаёт только рукопожатие.

Запросы самого расширения отфильтровываются по `chrome.runtime.id`.

## Страницы, куда расширение не попадает

`chrome://`, `chrome-extension://`, `about:`, `devtools:`, `view-source:` и магазин Chrome. Для них popup объясняет ограничение и не запускает мониторинг. Это ограничение платформы, а не отсутствующая функция.
